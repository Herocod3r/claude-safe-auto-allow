# External Integrations

**Analysis Date:** 2026-03-15

## APIs & External Services

**GitHub API:**
- Service: GitHub Releases API
- What it's used for: Automatic binary distribution and updates
  - Install script queries `https://api.github.com/repos/Herocod3r/claude-safe-auto-allow/releases/latest`
  - Downloads prebuilt binaries based on detected OS/architecture
  - Release workflow creates GitHub releases with cross-platform binaries
- SDK/Client: `curl` (no SDK)
- Auth: None required (public repo, unauthenticated API calls)

**Claude Code:**
- Service: IDE hook system
- What it's used for: Integration with Claude Code editor
  - Hooks into PreToolUse event - validates commands before execution
  - Hooks into PostToolUse event - offers to learn approved commands
- Integration method: Patches `~/.claude/settings.json` to register hook commands
- Hook commands: `claude-safety guard` and `claude-safety learn`

## Data Storage

**Databases:**
- Not applicable - no database backend

**File Storage:**
- Local filesystem only
  - Allowlist: `~/.claude-safe-auto-allow/safety-allowlist.json`
    - JSON format with pattern definitions
    - User-controlled, manually edited or auto-generated by learn hook
  - Version tracking: `~/.claude-safe-auto-allow/version.txt`
    - Single line: semantic version for update checking
  - Pending commands: `$TMPDIR/claude-safety-pending-{sessionID}.json`
    - Temporary files for inter-hook communication
    - Auto-cleaned after 60 seconds

**Caching:**
- Allowlist caching: In-memory only (loaded on each invocation)
- No persistent cache - simple file reads

## Authentication & Identity

**Auth Provider:**
- None - purely local operation
- No user authentication required
- No API credentials needed

**Session Handling:**
- Session ID provided by Claude Code in hook input
- Used to correlate guard/learn invocations
- Fallback to "unknown" if not provided

## Monitoring & Observability

**Error Tracking:**
- None - errors fail silently by design
- Guard/Learn commands exit with code 0 regardless of outcome
- Errors logged only via hook-specific output messages

**Logs:**
- Console output via JSON responses to Claude Code hooks
- Hook-specific context: `HookSpecificOutput` JSON structure
- No persistent log files
- No remote logging

**Debugging:**
- Binary can detect version mismatches and notify user via hook output
- Version comparison: Compares installed vs latest from GitHub

## CI/CD & Deployment

**Hosting:**
- GitHub Releases - distribution of prebuilt binaries
- Repository: `github.com/Herocod3r/claude-safe-auto-allow`

**CI Pipeline:**
- GitHub Actions (`.github/workflows/release.yml`)
- Trigger: Push git tags matching `v*`
- Steps:
  1. Test: `go test ./...` on ubuntu-latest
  2. Build: Cross-compile for darwin/linux × amd64/arm64
  3. Release: Upload artifacts via `softprops/action-gh-release@v2`

**Distribution:**
- Single curl-to-bash install:
  ```bash
  curl -fsSL https://raw.githubusercontent.com/Herocod3r/claude-safe-auto-allow/main/install.sh | bash
  ```
- Installer downloads from GitHub releases based on system detection

## Environment Configuration

**Required env vars:**
- None - application runs with zero environment variable dependencies

**Optional env vars:**
- Standard Go build env (GOOS, GOARCH) - only used during build

**Secrets location:**
- No secrets stored in codebase
- No API keys or credentials required
- User's allowlist stored locally in home directory

## Webhooks & Callbacks

**Incoming:**
- Claude Code hook system (not HTTP webhooks)
  - PreToolUse: Input contains `tool_name`, `tool_input` (with command), `session_id`
  - Responds with JSON: `decision`, `reason`, `hookSpecificOutput`
- Input via stdin, output via stdout

**Outgoing:**
- None - application does not make outbound webhooks
- GitHub API calls are pull-only (reading releases)

## Tool Integration

**Claude Code Hook Integration:**
- Entry point: Binary command path in `~/.claude/settings.json`
- Hook structure (JSON in settings):
  ```json
  {
    "hooks": {
      "PreToolUse": [{
        "_tag": "claude-safe-auto-allow",
        "hooks": [{"type": "command", "command": "{BINARY_PATH} guard"}]
      }],
      "PostToolUse": [{
        "_tag": "claude-safe-auto-allow",
        "hooks": [{"type": "command", "command": "{BINARY_PATH} learn"}]
      }]
    }
  }
  ```

**Inter-process Communication:**
- Guard → Learn: Via temporary JSON files in temp directory
  - File: `$TMPDIR/claude-safety-pending-{sessionID}.json`
  - Contains: Command, timestamp, dangerous flag
  - Lifetime: 60 seconds (enforced by learn stage)

## Release & Update Mechanism

**Version Checking:**
- Guard hook compares `buildVersion` (embedded at compile time) against `version.txt`
- If newer version available, notifies user via hook output
- Manual update: Re-run install script to download latest

**Rollback:**
- Settings backup created automatically during install
  - `~/.claude/settings.json.bak.{timestamp}`
- Previous hooks can be manually restored or uninstall script removes all hooks
